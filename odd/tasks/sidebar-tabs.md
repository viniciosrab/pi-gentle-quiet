# Sidebar tabs (pi-cinlodev-cute style) for gentle-quiet's side column

Tabbed side column after pi-cinlodev-cute (https://github.com/CinloDev/pi-cinlodev-cute, studied at a1add72):
the tabs it has, filled with gentle-quiet's own cards where they exist and cute's original design where they do not.
Branch `feat/sidebar-tabs`, stacked on `feat/sidebar-cards` (7969775).

## Specs

- **S1 — scope: side column only.** User: "Mas essa implementação só vai valer para a barra lateral, né? Quando não tiver a pétala toda, ele fica como tá, né? Não modifica, é só para a barra lateral, sabe?" Below the side-column breakpoint nothing changes (status line, cards, editor byte-identical).
- **S2 — existing things unchanged.** User: "o que já existe de nossas coisas a gente não vai alterar certo? A gente só vai tipo aqui o status, o contexto, o jeito que aparece os cards de subagente, enfim os tudo, nada." The Status, Context, Jobs, Agents and Todos cards keep their look and behavior.
- **S3 — the tabs.** User: "A gente só vai implementar esses negócios aí do single dev, sabe? Aí que aparece tipo o main vai ser o que a gente já tem né? Aí tem a parte do git, prof que é de parte dos arquivos, main que é do engram etc. Tu vai implementar todos, mas com as coisas que a gente tem aqui já do nosso jeito, entendeu? E as coisas que não tem você bota do jeito que tá ali originalmente do single dev, né?" Tabs (revised by L5): `1:MAIN 2:GIT 3:PROF 4:MEM 5:TREE`, active tab drawn `[ 5:TREE ]`.
  - MAIN: Status and Context fixed, then Jobs and Todos. The Agents card is not in the side column: it stays inline above the editor, as without the side column (L5).
  - GIT: cute's Git tab (branches + commit graph card, working tree / branch diff card, editor and diff launchers).
  - PROF: cute's profiles tab, with gentle-pi's profiles and gentle-quiet's plan usage instead of pi-sdd-profiles and CLIProxyAPI.
  - MEM: cute's memory tab (Engram card, handoff, ecosystem, tools); cards whose package is not installed are left out.
  - TREE: cute's project explorer (git status badges, folder toggles, `[ ↗ nvim ]` launcher).
- **S4 — no YouTube tab.** User: "E o do youtube, que é o 6 do youtube, você não precisa colocar, entendeu????"
- **S5 — tab switching as in cute:** left click on a tab in the tab bar, mouse wheel over the tab bar cycles tabs. The tab bar stays fixed at the top of the column.
- **S6 — TREE file preview:** a left click on a file in TREE opens a read-only preview pop-up inside Pi (Esc closes, scroll keys, `e` opens it in the editor tab as before), instead of a new editor tab per click.
- **S7 — preview polish:** a Markdown file shows rendered Markdown in the preview (raw source on a key); the pop-up's outline sits flush with its edge, with no black half-cell sticking out past the border over the conversation.
- **S8 — PR tab:** a `6:PR` tab after TREE lists the repository's open pull requests, one per row: number, title and a checks summary (✓ passed, ✗ failed, ⧗ running). The current branch's PR, when open, comes first with its detail: state and mergeability, each check with its state, unresolved review comments and the latest. No branch rows and no ahead/behind counts. With no open PR: "No open pull requests". A click opens the PR or the check in the browser. Data from `gh`.
- **S9 — MEM tab, what is useful:** replace the Stack · Ecosystem and Tools cards with (1) "Saved this session": the memories the agent saved or updated in this session (mem_save / mem_update), title and type, a click opens the memory in the read-only pop-up; (2) "Recalled this session": the memories the agent searched or read into the conversation (mem_search / mem_get_observation / mem_context); (3) Engram pending items (observations due for review, relations waiting for judgment) as a count, shown only when there are some. The Active Handoff folds to one row (`#920 · 1h ago · <goal first line>`) that a click expands to the full text. Stack shows only when an update is available. The Engram status card stays.
- **S10 — Symbols-style icons in TREE (revised, L19):** the TREE tab can draw its file and folder icons in the style of Miguel Solorio's "Symbols" VS Code theme using the Nerd Font glyphs the terminal font already has: Symbols' rules pick the icon (file name, then extension, then folder name) and its color; the glyph is the matching Nerd Font icon, chosen for a simple, thin look. A setting chooses emoji (today) or nerd. No extra font to install.
- **S11 — tab order setting:** the /gentle-quiet settings offer the side column's tab order: the user moves any tab up or down (for example PR to the second place); the tab bar shows the tabs in that order, numbered by position (1, 2, …), and the order is saved in gentle-quiet.json and survives /reload. A reset puts the default order back.
- **S12 — drag to reorder tabs:** in the tab bar the user presses on a tab, drags it sideways and releases it at a new place; while dragging the tab follows and the others make room; on release the order is saved like the Tab order setting (numbers follow position). A plain click without moving still switches tabs.
- **S13 — Engram card without Cloud:** the MEM tab's Engram card drops the Cloud section (host, state, dashboard, enroll/sync actions); it shows only local essentials: the local server's status and version, this project's memories, sessions and prompts, the memories across all projects, the database size on disk, and the pending row when there is one.

- **S14 — PR tab as a stack with verdicts (supersedes the layout of S8):** User: "A aba de PR aqui do nosso gente quiete Não entendi muito bem como funciona ela Tipo, a gente tem 3 pull requests abertas E aí... Como é que eu leio isso? [...] Não tem como eu trocar ali" then "Algo extremamente melhor para a expensa do usuário e melhor para a programação, melhor para a produtividade". Approved design ("sim"):
  - Every open PR is the same kind of row: `#N title` and flush right one verdict, the most serious of `✗ conflicts` > `✗ CI` > `✗ changes` > `⚠ N threads` > `⧗ CI` > `◌ draft` > `⧗ review` > `✓ ready`.
  - The PRs are drawn as their stack: a PR whose base is another open PR's head sits under it (`├ #19`, `└ #20`); no branch names.
  - A click on a PR's row expands its detail in place (mergeability, review, each check, each unresolved thread) or closes it; several PRs can be open at once (L29: "eu quero poder ir abrindo, sabe, todos Porque quando abre um fecha outro"). The current branch's PR is marked `◉` and starts expanded.
  - The stack's lines stay joined through an open PR's detail (L29: "Quando eu abro o acordeão, e vendo ele continuar ligando lá em cima, ele fica quebrado, ele fica pela metade"): the detail rows of a PR that has PRs under it carry the `│` that runs from its row down to its first `├`/`└`. A click on a check or a thread opens it in the browser; `[ Open ]` opens the PR.
  - On the current branch's PR only, `[ Fix N threads with agent ]` (and `[ Fix CI ]` when a check failed) fills Pi's editor with the threads (author, file:line, text, link) or the failed checks; it never sends: the user reviews and presses Enter. A draft already in the editor is kept, the text goes after it.
  - CI count (L28): every PR row with checks shows a CI chip before its verdict: `✓ CI 10/10`, `⧗ CI 5/10`, `✗ CI 9/10` (passed / checks that count, skipped ones left out; icon and color from the checks summary). When the verdict itself is about CI (`✗ CI`, `⧗ CI`) the chip stands for it and the verdict is not drawn twice; otherwise both show (`⧗ CI 5/10 ⚠ 2 threads`, `✓ CI 10/10 ✓ ready`). A PR without checks has no chip.
  - Layout (L31: "ficou tudo meio amontoado, meio confuso [...] Não tem uma [...] divisão ali clara pra saber até onde vai"): a PR's row has its title in bold; an open PR's detail is indented under the title (not under the marker), drawn quieter (muted), with dim section labels `Checks 2/3` and `Threads 4` before each list, and is followed by one blank row that still carries the stack's guide lines, so each PR reads as its own block.
  - Data: one `gh api graphql` call for every open PR. The current PR is matched by branch and head repository (a fork's PR with the same branch name is not it), found even past the first 30 PRs, and a PR with more review threads than were read never shows `✓ ready` for them.
- **S15 — popup of one running subagent or job:** User: "quando tem um subagente trabalhando ou até um job trabalhando [...] colocar um botãozinho ali [...] para que eu clique e ver e abra tipo popup do agente [...] o que que ele tá fazendo [...] em cada subagente que estiver trabalhando a opção de abrir [...] a janela direto nele [...] E na questão dos jobs também". Solved in gentle-quiet only (L30: "não temos que resolver somente no gentle quiete"); gentle-pi is not changed. Approved ("go"):
  - Each running subagent row of the Agents card (gentle-pi's widget, wrapped by gentle-quiet) ends with a `↗`; a click on that row opens a popup focused on that agent: its header (agent, status, model, elapsed) and its live thread (thinking, text, each tool with its output) drawn with gentle-pi's own thread renderer, so it looks like the alt+k window. It refreshes while open, follows the end while the agent works, scrolls with the keys, and closes with Esc or a click outside (as the file preview). Data: gentle-pi's presence file for this session (`~/.pi/agent/gentle-agents/presence/<sha256(sessionId)>.<incarnation>.activity.json`, the newest heartbeat).
  - Each running job row of the Jobs card ends with the same `↗`; a click opens a popup with the job's label, status, elapsed time and its live output (like tail -f). The output path is found in /proc (the Pi process holds the job's `gentle-jobs-*/<id>.log` open); off Linux the click opens `/gentle:jobs`.
  - The `↗` shows only while the agent or job works. The popup has no cancel/transcript buttons (alt+k stays for them). Two running tasks with the same agent and label: the newest opens.
  - When gentle-pi's file or renderer is not there or not readable, the click opens gentle-pi's list (`/gentle:agents`, `/gentle:jobs`) instead of failing.

- **S16 — the subagent popup in gentle-quiet's look (L33):** User: "quando a gente abre ali para ver que ele tá fazendo [...] ele não tem o mesmo visual que a gente implementou [...] todo o visual que eu digo das tools, que tem o quiet tools [...] isso teria como tipo ser implementado". Approved plan ("go"):
  - The popup reads the subagent's own Pi session file (`~/.pi/agent/gentle-agents/sessions/*.jsonl`, full tool calls with arguments and results), found through `gentle-agents/tasks/<id>.json`'s sessionPath for a finished task, else by a tool call id (`toolu_…`) from the presence thread that also appears in exactly one recent session file; the found path is remembered. The file is read incrementally (only appended bytes) about every 500 ms.
  - Tool calls are drawn with the same functions as the main conversation (quietCall's title row, quietSummary's summary and preview, the `└`, tones and icons); assistant text as Markdown, thinking dim.
  - Web tools (web_search, fetch_content, get_search_content, source_check), memory tools (mem_*, gentle-engram) and codemode draw in the popup as gentle-quiet draws them in the main conversation (L34), not as a bare name and "✓ N lines".
  - Before the first tool call, or when no session file is found or readable, the popup draws as today (presence thread).
  - The `↗` and the click also work on finished subagent rows when their task record names a session file.

## Decisions

- D1: no "✿ CINLODEV · GENTLE-SHELL ✿" banner (cute's brand); the tab bar opens the column.
- D2: helper modules live in `extensions/sidebar/` without an `index.ts`; Pi's `discoverExtensionsInDir` loads only files at the top level and subdirectories with `index.ts`/`index.js` or a `package.json` manifest, so they are not loaded as extensions. Deploy copies `extensions/gentle-quiet.ts` and `extensions/sidebar/` to `~/.pi/agent/extensions/`.
- D3: active tab kept in memory like cute (starts at MAIN), not persisted.
